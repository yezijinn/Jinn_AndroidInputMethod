如果这是给 Agent 的实现要求，建议定义成下面这一套，重点不是单纯“减少代码”，而是**降低主线程工作量、减少 View 重绘、减少数据库访问和避免无意义唤醒**。

### 输入法整体性能优化目标

1. **主线程零阻塞**
   - 主线程禁止执行数据库查询、加解密、文件 I/O、网络请求。
   - 剪贴板读取、历史查询、去重、加密、数据库写入全部放入后台线程。
   - 主线程只负责 UI 状态切换和最终结果提交。

2. **符号面板切换必须瞬时完成**
   - 分类切换只更新当前数据集和 Adapter。
   - 不重新创建整个面板。
   - 不重新 Inflate View。
   - 不修改 IME Window 高度。
   - 不修改 `layoutParams`。
   - 优先使用 `RecyclerView`，避免频繁创建/销毁大量 View。
   - 分类按钮采用 `selected` 状态切换，而不是重新构建顶部布局。

3. **剪贴板历史采用增量刷新**
   - 打开面板时只查询必要数据。
   - 不允许每次打开都执行全表 `deduplicate()`。
   - 新剪贴板内容采用增量插入。
   - 只有数据真正发生变化时才刷新 Adapter。
   - 避免 `notifyDataSetChanged()` 全量刷新。
   - 优先使用 `ListAdapter + DiffUtil`。

4. **剪贴板保存去重前置**
   - 同一内容不要重复写入数据库。
   - 计算 `content_hash` 后，在数据库层执行唯一性检查。
   - 使用 SQLite 唯一索引/事务保证并发情况下仍不会重复写入。
   - 避免通过“保存大量重复数据 → 打开页面 → 全表去重”的方式解决问题。

5. **避免重复监听**
   - `OnPrimaryClipChangedListener` 只注册一次。
   - 防止重复 `start()` 导致一次复制触发多个保存任务。
   - `stop()` 必须可靠解除监听。
   - 使用生命周期管理保证 IME 重建后不会产生多个 Listener。

6. **数据库优化**
   - SQLite 查询只获取 UI 必需字段。
   - 列表页不要一次解密全部历史记录。
   - 优先分页，例如：
     ```text
     LIMIT 50 OFFSET 0
     ```
   - 用户滚动到底部后再加载下一页。
   - `content_hash`、`created_at`、`category` 建立合理索引。
   - 避免每次打开面板执行全表扫描。

7. **加密优化**
   - AES-GCM 只在真正需要读取正文时解密。
   - 列表查询尽可能使用元数据。
   - 不要在后台循环中重复解密同一条数据。
   - UI 已经显示过的数据可以进行短生命周期内存缓存。

8. **UI 渲染优化**
   - 避免 `requestLayout()` 高频调用。
   - 避免 `invalidate()` 高频调用。
   - 避免反复修改 `visibility + layoutParams + height`。
   - IME 总高度保持稳定。
   - 候选栏、底部栏、键盘区域尽量保持 View 树稳定。
   - 面板之间切换优先使用 `VISIBLE / INVISIBLE`。
   - 不使用动画或复杂动画作为默认行为。

9. **减少卡顿的关键原则**

   ```text
   点击按钮
       ↓
   修改状态
       ↓
   更新少量 View
       ↓
   立即显示结果

   数据查询
       ↓
   后台线程
       ↓
   得到结果
       ↓
   主线程提交 Diff
   ```

   不允许：

   ```text
   点击按钮
       ↓
   查询数据库
       ↓
   去重
       ↓
   解密几十条数据
       ↓
   创建几十个 View
       ↓
   requestLayout
       ↓
   notifyDataSetChanged
       ↓
   用户看到界面
   ```

### 电量优化

**输入法属于高频常驻应用，电量优化优先级很高。**

- 禁止高频 `Handler.postDelayed()` 轮询。
- 禁止固定周期刷新剪贴板数据库。
- 没有事件时不要主动唤醒 CPU。
- 剪贴板变化采用事件驱动，而不是轮询。
- WebSocket 使用合理的心跳间隔，不要高频 Ping。
- ASR 未使用时停止相关音频资源。
- 不使用功能时释放麦克风、网络、线程池等资源。
- Root 防护如果存在定时轮询，应改成**最低必要频率**，并提供开关。
- 不在 `onStartInputView()` 中执行重量级任务。
- 不在每次获得焦点时重新初始化数据库、Adapter、监听器。
- 不重复创建线程，使用一个受控的 `Executor` / `CoroutineDispatcher`。

### 推荐线程模型

```text
                 JinnIme
                    │
        ┌───────────┼───────────┐
        ↓           ↓           ↓
      UI线程       IO线程      ASR线程
        │           │           │
    View操作      SQLite       WebSocket
    状态切换      AES-GCM       ASR
    输入提交      Clipboard     音频
        │
        └─────── 绝不阻塞 ───────┘
```

推荐 Kotlin 使用：

```text
Dispatchers.Main
Dispatchers.IO
CoroutineScope
SupervisorJob
```

避免项目中大量：

```kotlin
Thread { ... }.start()
```

因为大量短生命周期 Thread 会产生额外调度和内存开销。

### 最重要的性能原则

整个项目统一遵循：

> **事件驱动、增量更新、异步 I/O、稳定 View 树、避免全量刷新、避免无意义唤醒。**

尤其是你的**输入法键盘、剪贴板、符号面板**，应该把“点击后立即响应”作为第一优先级；数据库、加密、历史数据加载全部放到响应之后异步完成。这样可以同时降低**操作延迟、UI 卡顿和后台耗电**。
