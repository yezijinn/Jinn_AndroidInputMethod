==================================================
新增问题：连续拼音分词歧义
==================================================

用户反馈：

输入：

xuni

当前算法：

xun + i

原因：

PinyinSegmenter 当前采用贪心最长匹配。

但是用户期望：

xu + ni

从而能够召回：

虚拟

这是典型的：

Pinyin Segmentation Ambiguity
拼音分词歧义问题。

--------------------------------------------------
强制修改要求
--------------------------------------------------

禁止继续使用：

“最长合法拼音音节 = 最优分词结果”

作为最终算法。

最长匹配只能作为候选路径之一。

对于：

xuni

至少应该能够生成：

xun + i
xu + ni

然后结合词库进行路径评分。

--------------------------------------------------
推荐流程
--------------------------------------------------

rawInput
↓
PinyinSegmenter
↓
生成多个合法 SegmentPath
↓
DictionaryLookup
↓
PathScorer
↓
BestPath / Top-K Path
↓
Candidate Generation
↓
Candidate Ranking

--------------------------------------------------
必须支持的歧义示例
--------------------------------------------------

xuni
→ xu + ni
→ 虚拟

xian
→ xi + an
→ 先
同时允许其他合法解析

nimen
→ ni + men
→ 你们

women
→ wo + men
→ 我们

shanghai
→ shang + hai
→ 上海

--------------------------------------------------
路径评分
--------------------------------------------------

必须研究 libpinyin / RIME 中是否存在类似：

segmentation scoring
dictionary constrained segmentation
sentence decoding
candidate path
lattice
beam search

然后再确定最终算法。

优先考虑：

Dynamic Programming
或
Beam Search

不要直接实现无限 DFS。

--------------------------------------------------
重要原则
--------------------------------------------------

合法拼音 ≠ 正确分词。

例如：

xun + i

语法上可能是合法拼音分割，

但如果词库中：

xu + ni
→ 虚拟

具有明显更高的词库命中和语言模型评分，

则：

xu + ni

应该获得更高优先级。

--------------------------------------------------
测试要求
--------------------------------------------------

新增：

xuni → xu + ni

并验证最终能够召回：

虚拟

同时测试：

nimen → ni + men
women → wo + men
shanghai → shang + hai

不得因为取消贪心最长匹配而导致：

候选数量爆炸
查询明显变慢
普通拼音输入准确率下降。

--------------------------------------------------
回归要求
--------------------------------------------------

必须对比修改前后：

1. 完整拼音
2. 连续拼音
3. 不完整拼音
4. 双拼
5. 英文

重点确认：

“最长匹配”从：

最终决策

变成：

候选路径生成策略。

最终决策必须由：

拼音合法性
+
词库命中
+
词频/候选评分

共同决定。
