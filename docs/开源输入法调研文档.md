## 二、引擎级深度剖析

### 2.1 libime（Fcitx5）

**仓库**：https://github.com/fcitx/libime
**语言**：C++（可 JNI 接入 Android）
**地位**：Fcitx5 的输入法核心库，候选词引擎的新一代设计，**综合参考价值最高**。

#### 2.1.1 整体架构

```
输入串（如 nihk 双拼）
   ↓ PinyinEncoder::parseUserShuangpin() / parseUserPinyin()
SegmentGraph（音节切分图，含歧义多路径）
   ↓ PinyinDecoder::decode()（buildLattice + forwardSearch + backwardSearch）
Lattice（词典匹配网格，每个节点 = 词 + 音节跨度）
   ↓ PinyinContext::update() 汇总
候选列表（N-Best 整句 + 词候选 + 单字）
```

#### 2.1.2 候选生成核心：`PinyinContext::update()`

**文件**：`src/libime/pinyin/pinyincontext.cpp` L672-840
**Permalink**：https://github.com/fcitx/libime/blob/c8fa4906a74f3b280f9be9a1533ddc749dceaeb0/src/libime/pinyin/pinyincontext.cpp#L672-L840

候选生成分三步：

**① 先放 N-Best 整句候选**（L712-714）——动态规划解码出的完整句子优先：
```cpp
for (size_t i = 0, e = d->lattice_.sentenceSize(); i < e; i++) {
    d->candidates_.push_back(d->lattice_.sentence(i));
}
```

**② 按「音节位置从后往前」枚举 lattice 节点**（L719-781）——覆盖音节多的词先进入候选：
```cpp
for (size_t i = graph.size(); i > 0; i--) {
    for (const auto &latticeNode : d->lattice_.nodes(&graphNode)) {
        if (latticeNode.from() == bos &&          // 从起点开始的词典词
            !isCorrection()) {
            d->candidates_.push_back(latticeNode.toSentenceResult(adjust));
        }
    }
}
```
位置 i 从最后一个音节边界倒序遍历 → 长词（覆盖多音节）先被 push。

**③ 关键机制「距离惩罚」**（L722-730）——这是「按音节数逐级递减」的**评分本质**：
```cpp
auto distancePenalty = d->ime_->model()->unknownPenalty() /
                       PINYIN_DISTANCE_PENALTY_FACTOR;
// distance = 该节点到终点的剩余音节数
auto adjust = static_cast<float>(distance) * distancePenalty;
```
`unknownPenalty` 为负值 → **剩余音节越多（词越短）分越低** → 短词自然排在长词后；全覆盖整词 `distance=0` 不受惩罚。libime 不靠显式分组，而靠分数排序实现「2字词 → 单字」的平滑递减。

**④ 单音节词不占候选配额**（L811-825）——`encodedPinyin().size() == 2` 判定单音节，`wordCandidateLimit` 只限制多音节词，保证单字永远有得显示。

#### 2.1.3 动态规划切分：`decoder.cpp`

**文件**：`src/libime/core/decoder.cpp`
**Permalink**：https://github.com/fcitx/libime/blob/c8fa4906a74f3b280f9be9a1533ddc749dceaeb0/src/libime/core/decoder.cpp#L78-L244

- `buildLattice()`（L78-164）：用 `dict_->matchPrefix` 枚举所有可能的词节点，按 frame 分组并做 beam 剪枝
- `forwardSearch()`（L166-244）：**Viterbi 前向**——每个节点取分数最高的前驱 `node.setPrev(maxNode)`
- `backwardSearch()`（L256-358）：**N-Best 后向**——从 EOS 用最大堆回溯，得到多条整句

#### 2.1.4 词典匹配：`pinyindictionary.cpp`

**文件**：`src/libime/pinyin/pinyindictionary.cpp` L594-688
**Permalink**：https://github.com/fcitx/libime/blob/c8fa4906a74f3b280f9be9a1533ddc749dceaeb0/src/libime/pinyin/pinyindictionary.cpp#L594-L688

`findMatchesBetween()`：取两个音节边界之间的拼音 → `stringToSyllables` 切成音节 → **沿 Trie 逐音节下探** `traverseAlongPathOneStepBySyllables()`。匹配失败时插入「无效词」保证 lattice 连通：
```cpp
if (!matchWords(context, newPaths)) {
    // 拼不出词时，把原始拼音当单字节点塞进去，让图不断裂
    WordNode word(pinyin, InvalidWordIndex);
    context.callback_(vec, word, invalidPinyinCost, nullptr);
}
```

#### 2.1.5 双拼/全拼切分：`pinyinencoder.cpp`

**文件**：`src/libime/pinyin/pinyinencoder.cpp` L182-301（全拼）、L352（双拼）
**Permalink**：https://github.com/fcitx/libime/blob/c8fa4906a74f3b280f9be9a1533ddc749dceaeb0/src/libime/pinyin/pinyinencoder.cpp#L182-L301

`parseUserPinyin` 用**优先队列 BFS**切分：每个位置尝试 `longestMatch()` 最长音节；对歧义边界（如 `zhuni → zhu|ni`）同时产生两条边 `addNext(top, top+size)` 和 `addNext(top, top+size-1)`，让后续 DP 自己选。`parseUserShuangpin` 同理，只是先过双拼 profile 转全拼。

> 对照：CapsWriterIME 当前 `PinyinEngine.segment()` 是贪心最长匹配（只保留一条边），是 libime「保留多路径」的简化版。对无歧义音节足够，但 `zhuni` 这类边界会有切分偏差。

#### 2.1.6 智能预测：`pinyinprediction.cpp`（重点）

**文件**：`src/libime/pinyin/pinyinprediction.cpp` L42-141
**Permalink**：https://github.com/fcitx/libime/blob/c8fa4906a74f3b280f9be9a1533ddc749dceaeb0/src/libime/pinyin/pinyinprediction.cpp#L42-L141

双通道预测（用户选中「你好」后预测「吗/像」的现成实现）：

**通道① 语言模型**：`Prediction::predictWithScore(state, sentence, maxSize)`——用历史词（已选词）做 bigram/trigram 概率 `P(next|history)`。

**通道② 词典续写**（L103-131，核心）：
```cpp
d->dict_->matchWordsPrefix(
    lastEncodedPinyin.data(), lastEncodedPinyin.size(),
    [this, &sentence, ...](std::string_view, std::string_view hz, float cost) {
        // 词库里有"你好吗/你好像"，且以已选词"你好"开头
        if (sentence.back().size() < hz.size() &&
            hz.starts_with(sentence.back())) {
            // 截出新增部分："吗"、"像"
            std::string newWord(hz.substr(sentence.back().size()));
            // 分数 = 词典 cost + 模型分
            std::tuple<...> newItem{std::move(newWord),
                                    cost + model()->singleWordScore(prevState, hz),
                                    PinyinPredictionSource::Dictionary};
        }
    });
```
即：**用已选词的拼音前缀查词库中「以该词开头的更长词」，截掉已选部分得到预测词**。

**工程坑**（L91-96 注释明确）：「无」可能来自「无聊」这类跨词边界，需要调整预测分补偿，避免来源污染。

#### 2.1.7 用户学习：`historybigram.*`

`HistoryBigram::fillPredict`（https://github.com/fcitx/libime/blob/c8fa4906a74f3b280f9be9a1533ddc749dceaeb0/src/libime/core/historybigram.h#L64-L72 ）把用户每次选择的词对写进 trie，下次查询一并返回。这是「越用越准」的机制。

### 2.2 AOSP PinyinIME

**官方仓库**：https://android.googlesource.com/platform/packages/inputmethods/PinyinIME/
**Android Studio 可编译 fork**：https://github.com/lizhangqu/PinyinIME（218★）
**语言**：C++（jni）+ Java
**地位**：Google 拼音旧版开源，C 风格矩阵搜索，**「按音节数逐级递减」的最直白实现，最适合移植**。

#### 2.2.1 核心：`prepare_candidates()` —— 逐级递减取词

**文件**：`jni/share/matrixsearch.cpp` L1131-1189
**Permalink**：https://github.com/opensourcechipspark/platform_packages_inputmethods_PinyinIME/blob/ca119d20e812624a75c84e6987c61b94047aa605/jni/share/matrixsearch.cpp#L1131-L1189

```cpp
void MatrixSearch::prepare_candidates() {
  // 最长可取 = 剩余未固定的音节数
  uint16 lma_size_max = kMaxLemmaSize;
  if (lma_size_max > spl_id_num_ - fixed_hzs_)
    lma_size_max = spl_id_num_ - fixed_hzs_;
  uint16 lma_size = lma_size_max;

  // 先拿整句候选，用于剔除与整句重复的短语
  pfullsent = get_candidate0(fullsent, kMaxLemmaSize + 1, &sent_len, true);

  lpi_total_ = 0;
  size_t lpi_num_full_match = 0;
  while (lma_size > 0) {                      // ← 从最长音节数递减到 1
    lma_num = get_lpis(spl_id_ + fixed_hzs_, lma_size,   // 取"恰好 lma_size 个音节"的词
                       lpi_items_ + lpi_total_, ...);
    if (lma_num > 0) {
      lpi_total_ += lma_num;
      pfullsent = NULL;
    }
    if (lma_size == lma_size_max) {
      lpi_num_full_match = lpi_total_;   // 记录全匹配词数
    }
    lma_size--;
  }
  // 部分匹配（短词）按统一分数排序
  myqsort(lpi_items_ + lpi_num_full_match, lpi_total_ - lpi_num_full_match, ...);
}
```

**这就是「按音节数逐级递减」的语义**：输入 `nihao` → `spl_id_num_ = 2` 个音节 → `lma_size` 从 2 递减：
- `lma_size=2`：取 2 音节词（你好）
- `lma_size=1`：取 1 音节单字（ni → 你/尼/泥，hao → 好/号/毫）

输入 3 音节则 3 → 2 → 1，天然实现「先 3 字词、再 2 字词、再 1 字词」。

#### 2.2.4 智能预测：`inner_predict()`

**文件**：`jni/share/matrixsearch.cpp` L1844-1946
**Permalink**：https://github.com/opensourcechipspark/platform_packages_inputmethods_PinyinIME/blob/ca119d20e812624a75c84e6987c61b94047aa605/jni/share/matrixsearch.cpp#L1844-L1946

固定文本（已选词）后缀逐级预测，**长度越长优先级越高**：
```cpp
for (size_t len = fixed_len; len > 0; len--) {
  // 历史长于 1 且 len==1 时：先看最近 n 字是否成词，再决定预测来源
  if (fixed_len > 1 && 1 == len && 0 == res_total) {
    bool nearest_n_word = false;
    for (size_t nlen = 2; nlen <= fixed_len; nlen++) {
      if (dict_trie_->get_lemma_id(fixed_buf + fixed_len - nlen, nlen) > 0)
        nearest_n_word = true;
    }
    res_this = dict_trie_->predict_top_lmas(nearest_n_word ? len : 0, ...);
  }
  res_this = dict_trie_->predict(fixed_buf + fixed_len - len, len, ...);  // 系统词典
  if (user_dict_) res_this += user_dict_->predict(...);                   // 用户词典
}
// 优先"基于更长历史"的预测
myqsort(npre_items_, res_total, sizeof(NPredictItem), cmp_npre_by_hislen_score);
```
已选「你好」→ 先试 2 字前缀「你好」预测整词（你好吗/你好像），再试 1 字前缀「好」预测，综合排序。

### 2.5 Rime/librime

**仓库**：https://github.com/rime/librime（核心 4546★）＋ https://github.com/osfans/trime（Android 前端 4506★）
**语言**：C++（librime）+ Kotlin（trime）
**地位**：配置驱动，词库方案丰富；**核心无「提交后联想」**，靠插件。

#### 2.5.1 候选生成链

- `Engine::TranslateSegments` → 各 Translator 的 `Query()`
- 拼音翻译器 `ScriptTranslator::Query`（`src/rime/gear/script_translator.cc` L202）：输入 → `ScriptSyllabifier::BuildSyllableGraph()` 切音节图 → Prism 词典 Lookup → MakeCandidate / 短语合并
- 音节切分在 `src/rime/algo/syllabifier.cc` L26：`BuildSyllableGraph(input, prism, &graph)` 用**双数组 Trie（Prism）**找所有合法音节跨度，构建 `SyllableGraph`（`vertices` = 边界位置，`edges` = 音节拼写）

Rime 候选组织与 libime 不同：**短语优先由词典 Lookup 直接返回整串匹配**，单字/简拼候选由 `matcher` 的 `Spans`（音节跨度）控制，`phrase_length` 参与排序权重。

#### 2.5.2 智能预测：librime-predict 插件

**仓库**：https://github.com/rime/librime-predict

- **数据结构**（`src/predict_db.cc` L80-169）：一个 darts 双数组 trie，**key = 已上屏的词**（含 `$` 表示空上下文），**value = 有序候选词数组**。`Lookup` 一次 `exactMatchSearch`——**纯关联表，零计算**：
  ```cpp
  predict::Candidates* PredictDb::Lookup(const string& query) {
    int result = key_trie_->exactMatchSearch<int>(query.c_str());
    if (result == -1) return nullptr;
    return Find<predict::Candidates>(result);
  }
  ```
- **触发机制**（`src/predictor.cc` L56-98）：`Processor` 挂 `select_notifier` / `update_notifier`，选词提交后 `commit_history()` 非空且类型非标点 → 取 `last_commit.text` 查库
- **候选注入**（`src/predict_engine.cc` L47-71）：往 composition 塞 `prediction` tag 的 segment，由 `predict_translator` 翻译成候选

> ⚠️ `librime-predict` 只负责查询，`predict.db` 的构建工具不在仓库里（需上游用词频/语料统计「词→下一词」表）。

## 四、候选词生成算法专题

### 4.1 按音节数逐级递减（我们已采用）

**参考**：AOSP PinyinIME `prepare_candidates()` L1131-1189

**核心思想**：输入切分为 N 个音节后，候选按「音节数」从 N 递减到 1 组织：
- 输入 N 个音节 → 先 N 字词、再 N-1 字词、…、最后 1 字单字
- **不显示超出拼音数量的词**（杜绝 nihaoa/nihaoma 这类超长词）

**CapsWriterIME 落地**（已实现于 `PinyinEngine.query`）：
```kotlin
for (k in syllables.size downTo 1) {
    val key = syllables.take(k).joinToString("")
    for (k2 in phraseKeysOf(key)) {
        phrasesByPinyin[k2]?.let { result.addAll(it.take(MAX_PHRASES)) }
    }
    if (k == 1) {
        for (syl in syllables) {
            result.addAll(charsFor(syl).take(MAX_CHARS))
        }
    }
}
```

**真机验证结果**：
- `nihk → nihao → [你好, 你, 拟, 尼]`（2 字词 + 单字）
- `nihkma → nihaoma → [你好吗, 你好, 你]`（3 字 → 2 字 → 1 字）

### 4.2 Lattice 动态规划 + 距离惩罚

**参考**：libime `decoder.cpp` + `pinyincontext.cpp` L672-840

**距离惩罚原理**：候选统一评分 `score = 词频分 - 剩余未匹配音节数 × penalty`，短词因「后面还欠着音节」分数被压低，自然排在长词后。比显式分组更平滑，且天然支持「部分匹配词」排序。

**适用场景**：需要多音字消歧、模糊音、错拼纠错时。对 CapsWriterIME 当前「双拼 + 常用词」场景，AOSP 的逐级递减已够用，Lattice 是进阶方向。

### 4.3 智能预测的三种实现路径

| 路径 | 参考项目 | 数据 | 查询成本 | 排序依据 | 实现难度 |
|------|----------|------|----------|----------|----------|
| **A. 词典续写** | libime `pinyinprediction.cpp` L42-141 | 现成短语词典 | `matchWordsPrefix` 按拼音前缀拆词 | 词典代价 + LM 分 | 低 |
| **B. 纯关联表** | librime-predict `predict_db.cc` | 预建 `词→候选[]` 表 | 一次 trie 精确查找 | 建库时定的权重 | 低 |
| **C. 语言模型** | libime `libime_prediction.cpp` + `prediction.cpp` | 离线 ARPA→关联表 | trie 前缀查 + 候选 LM 打分 | LM state 精确分 | 高 |

**推荐路径（性价比最高）**：先做 A（从短语库提取关联表 + 频率排序），架构留出 `predictor` 接口；后续要提升准确率时把排序函数换成 bigram 打分（路径 C），数据层不变。libime 的 `PinyinPrediction` 双来源合并 + 最大堆截断（L76-131）是现成架构模板。

### 5.4 词库格式对照（与 CapsWriterIME 现有格式）

| 项 | Rime dict.yaml | CapsWriterIME `pinyin_phrases.txt` |
|----|----------------|-------------------------------------|
| 方向 | `词 → 拼音` | `拼音 → 词` |
| 拼音分隔 | 空格分隔音节（`a ba`） | 紧凑串（`aba`） |
| 同音词 | 每词一行 | `|` 连接 |
| 权重 | 有（`sort: by_weight`） | 无（按文件顺序） |

**转换要点**：去空格 → 反转键值 → 同拼音聚合用 `|` → 权重转排序或丢弃。儿化音 `ge er`、`nve/lve`（虐/略）等注音约定需注意。
