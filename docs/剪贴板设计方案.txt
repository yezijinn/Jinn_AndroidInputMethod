# Android 输入法「安全剪贴板」设计与实现方案

你是一名资深 Android 系统开发、安全工程、输入法和隐私保护开发工程师。

请在现有 Android 输入法项目中设计并实现一个“安全剪贴板”功能。

==================================================
一、当前项目状态
==================================================

这是一个已经基本完成的 Android 手机输入法项目。

当前状态：

- 输入法 UI 已经基本完成
- 键盘已经可以正常使用
- 候选栏已经可以正常使用
- 输入法核心功能整体可用
- UI 只剩少量细节调整

因此：

【禁止重做现有 UI】
【禁止重构现有键盘】
【禁止更换现有 UI 框架】
【禁止修改已经正常工作的输入逻辑】

本任务重点是增加：

1. 剪贴板历史
2. 剪贴板隐私保护
3. 加密存储
4. 剪贴板搜索
5. APP 访问权限管理
6. 敏感内容保护
7. Root 超级权限增强功能

Root 功能必须是：

【可选扩展功能】

普通 Android 权限模式必须可以独立正常工作。

没有 Root：

输入法的普通剪贴板功能必须完整可用。

有 Root：

用户可以主动开启“Root 增强模式”，获得额外的系统级剪贴板隐私控制能力。

==================================================
二、核心设计原则
==================================================

整个系统分为两个独立层级：

【普通模式】

使用 Android 官方 API 和普通应用权限。

主要管理：

“本输入法自己的剪贴板历史”。

【Root 增强模式】

用户主动授权 Root 后启用。

增加：

“系统级 Clipboard Firewall / 剪贴板防火墙”。

两种模式必须解耦。

普通模式不能依赖 Root。

Root 模式不能破坏普通模式。

==================================================
三、必须明确 Android 权限边界
==================================================

普通 Android APP 无法仅通过自身权限强制阻止其他 APP 使用 Android Framework 的 ClipboardManager。

因此普通模式：

可以控制：

- 本输入法是否读取系统剪贴板
- 本输入法是否保存剪贴板历史
- 本输入法自己的历史数据库
- 本输入法提供的第三方历史访问接口
- 用户对第三方 APP 的历史访问授权

但不能声称：

“普通模式可以阻止所有 APP 读取 Android 系统 ClipboardManager”。

这是技术边界。

Root 模式才允许进一步研究系统级：

ClipboardService / Framework

拦截。

==================================================
四、整体架构
==================================================

设计为：

                 Android System Clipboard
                          │
                          ↓
                    ClipboardManager
                          │
                          ↓
                 Clipboard Controller
                          │
                ┌─────────┴─────────┐
                ↓                   ↓
          普通权限模式          Root 增强模式
                │                   │
                ↓                   ↓
       Private Clipboard      Clipboard Firewall
           History                 │
                │             ┌────┼────┐
                │             ↓    ↓    ↓
                │           Read Listener Write
                │             │    │    │
                │             └────┼────┘
                │                  ↓
                │            Policy Engine
                │                  ↓
                └──────────────→ 权限判断
                                   │
                           ALLOW / DENY
```

==================================================
五、普通权限模式
==================================================

普通模式是默认模式。

用户安装输入法后：

不需要 Root。

不需要 Magisk。

不需要 LSPosed。

不需要修改系统。

不需要系统签名。

普通模式必须可以独立运行。

==================================================
六、普通模式：系统剪贴板
==================================================

默认：

其他 APP 按 Android 系统机制正常写入系统剪贴板。

本输入法根据 Android 系统版本和官方 API 规则决定是否读取。

不要尝试在普通模式下：

- Hook ClipboardService
- 修改系统 Framework
- 拦截其他 APP 的 ClipboardManager
- 虚假实现系统级读取阻断

==================================================
七、普通模式：自己的剪贴板历史
==================================================

本输入法建立独立的：

Private Clipboard History

系统剪贴板内容如果符合保存策略：

Android System Clipboard
        ↓
Clipboard Controller
        ↓
Privacy Check
        ↓
Sensitive Content Check
        ↓
Encryption
        ↓
Private Clipboard Database

这是本输入法真正可以完全控制的数据。

禁止读取本输入法的 Clipboard History。

例如：

com.example.app2

十一、第三方 APP 身份验证
==================================================

禁止：

让 APP 自己提交：

然后直接相信。

必须通过 Android IPC/Binder 等机制获得真实调用方身份。

流程：

 ↓

 ↓

 ↓
最多返回 3 条
 ↓
返回结果

未授权：

直接拒绝。

十三、加密存储

==================================================
三十四、Root 模式攻击边界
==================================================

必须明确：

Root 可以增强系统级控制。

但 Root 本身意味着：

root 进程拥有极高权限。

如果攻击者已经控制：

root
内核
系统 Framework
输入法进程

则无法保证：

“绝对无法读取明文”。

因此项目文档必须明确：

Root 模式主要防御：

普通第三方 APP
未经授权的 ClipboardService 调用
Clipboard Listener
系统级普通访问路径

不保证防御：

内核级攻击
恶意 root 进程
被 Hook 的输入法进程
被修改的系统
设备完全失陷

不要宣传：

“Root 后绝对安全”。

普通模式：

==================================================
四十三、最重要的实现原则
==================================================

1. 普通模式必须独立工作。
2. Root 只是增强功能。
3. Root 失败不能影响输入法正常工作。
4. 普通模式不要伪造系统级 Clipboard 权限控制。
5. Root 模式才研究 Framework / ClipboardService 层控制。
6. 系统 Clipboard 和本输入法 Clipboard History 必须分离。
7. Clipboard History 必须加密存储。
8. 密钥必须使用 Android Keystore。
9. 不允许自己发明加密算法。
10. 不允许日志输出剪贴板正文。
11. 敏感内容默认不长期保存。
12. 第三方 APP 默认禁止访问本输入法历史。
13. 授权 APP 每次最多读取最新 3 条。
14. 3 条限制必须在 IPC/API 层强制执行。
15. 必须防止分页、重复请求、并发请求绕过限制。
16. Root 模式必须有明确的安全边界。
17. 不要为了剪贴板功能重做现有输入法 UI。
18. 不要修改已经正常工作的输入逻辑。
19. 开发前必须先分析现有项目。
20. 先完成普通模式，再实现 Root 增强模式。
