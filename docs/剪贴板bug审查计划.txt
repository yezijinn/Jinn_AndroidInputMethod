```text
五十五、最重要的设计原则
==================================================

整个剪贴板模块必须遵守：

【数据与 UI 分离】

【完整历史是唯一数据源】

【visibleItems 是派生数据】

【分类只是过滤条件】

【搜索只是过滤条件】

【position / idx 只是 UI 位置】

【Stable ID 才是 Item 身份】

【Item View 必须绑定真实 Item 或 Stable ID】

【旧 View 必须失效】

【空列表不是返回条件】

【失败不是返回条件】

【只有明确成功的 Item 操作才允许关闭剪贴板】

【InputConnection 必须经过安全检查】

【selection 参数必须经过验证】

【任何外部数据都不能导致输入法 Crash】

【任何剪贴板明文不得进入日志】

最终目标不是：

“没有发现 Crash”。

而是：

即使用户以非常规顺序快速操作：

分类
→ 搜索
→ 删除
→ 收藏
→ 去重
→ 切换分类
→ 点击旧位置
→ 切换输入框
→ InputConnection 变化

剪贴板仍然：

不崩溃
不误粘贴
不错误返回
不丢数据
不泄露隐私
不产生错误状态。
```

### 这版和前面版本最大的区别

我建议 Agent 最终围绕 **4 个核心不变量**审查，而不是围绕一个个按钮修 Bug：

| 不变量 | 要求 |
|---|---|
| **数据不变量** | `allItems` 永远是完整历史，分类/搜索绝不能破坏它 |
| **身份不变量** | `position/idx` 只是位置，`id` 才是 Item 身份 |
| **事件不变量** | 分类点击、Item 点击、返回点击绝不能互相串线 |
| **导航不变量** | 只有有效 Item 完成粘贴后才能触发返回；空状态/异常状态绝不能自动返回 |

尤其是你现在已经遇到的两个问题：

```text
currentItems[idx]
```

和：

```text
setSelection(0)
```

本质上都是同一个工程问题：

> **代码假设“当前状态一定有效”，但 Android IME 的 UI、InputConnection、数据列表都可能在异步和生命周期变化中失效。**

因此最终设计应该是：

```text
用户操作
   ↓
验证 UI 状态
   ↓
验证数据身份
   ↓
验证数据仍存在
   ↓
验证 InputConnection
   ↓
验证参数范围
   ↓
执行操作
   ↓
确认成功
   ↓
更新 UI
   ↓
必要时导航
```

而不是：

```text
点击
 ↓
直接操作数组 / InputConnection
 ↓
出错后 catch
```
