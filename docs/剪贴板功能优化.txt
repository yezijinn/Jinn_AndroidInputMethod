```text
# 任务：完善 Android 输入法剪贴板功能

你正在维护一个已经基本完成的 Android 手机输入法项目。

本任务只针对【剪贴板功能】进行功能完善和代码优化。

==================================================
一、最高优先级要求
==================================================

1. 先完整检查当前项目已有的剪贴板实现。
2. 理解现有 UI、数据结构、状态管理和导航逻辑。
3. 不要直接重写整个剪贴板模块。
4. 优先在现有架构上进行最小必要修改。
5. 不得破坏现有输入法功能。
6. 不得破坏现有剪贴板隐私权限设计。
7. 不得修改与本任务无关的 UI。
8. 修改后必须编译并执行相关测试。
9. 发现现有代码存在 Bug 时，修复根因，不要用临时 workaround。
10. 不确定是否可以删除的代码必须先保留。

==================================================
二、剪贴板最终功能结构
==================================================

剪贴板一级分类固定为：

全部
网址
隐私
数字
收藏

不得额外增加：

文本
代码
地址
电话
其他

等一级分类。

其中：

【全部】
显示所有剪贴板记录。

【网址】
自动分类 URL、网站地址、深链接等。

【隐私】
只能由用户主动标记。

APP 不得自动将内容分类为隐私。

【数字】
自动分类电话、验证码、数字串、订单号、金额等。

【收藏】
用户主动收藏的记录。

注意：

【收藏不是普通分类，而是独立状态/标签。】

因此一条记录可以同时属于：

网址 + 收藏

或者：

数字 + 收藏

==================================================
三、历史记录排序
==================================================

剪贴板记录：

最新在最上面。

最旧在最下面。

例如共有 8 条：

8 = 最新
7
6
5
4
3
2
1 = 最旧

每条记录开头显示当前 UI 序号。

例如：

8  https://example.com
7  Hello World
6  adb shell
...
1  最旧内容

==================================================
四、序号规则
==================================================

UI 序号不是数据库主键。

数据库内部 ID 必须保持稳定。

UI 序号根据当前历史记录动态计算。

发生以下情况后重新计算：

- 新增
- 删除
- 清理重复
- 清空
- 其他导致列表变化的操作

始终保证：

最大序号 = 最新记录

1 = 当前列表中的最旧记录

禁止出现：

8
7
5
3
1

这种不连续的 UI 序号。

必须重新排列为：

5
4
3
2
1

如果当前列表只有 5 条记录。

==================================================
五、点击记录：直接粘贴
==================================================

用户单击某条剪贴板记录时：

不要只复制到系统剪贴板。

必须直接执行：

当前记录内容
    ↓
通过当前 InputConnection
    ↓
插入当前编辑框
    ↓
收起剪贴板
    ↓
退出当前剪贴板功能页面
    ↓
返回上一层输入法页面

行为等价于：

系统导航返回按钮

但是注意：

这里的“返回”是返回输入法内部上一页面。

不能退出输入法。

不能退出当前 APP。

不能关闭整个键盘。

例如：

用户点击：

8  Hello World

应立即：

InputConnection.commitText("Hello World")

然后：

剪贴板页面关闭。

回到之前的输入法页面。

==================================================
六、点击记录的兼容性
==================================================

粘贴操作必须使用当前有效 InputConnection。

执行前检查：

- 当前 InputConnection 是否有效
- 当前编辑器是否仍然存在
- 当前输入法是否仍处于可输入状态

如果 InputConnection 无效：

不要崩溃。

进行安全处理。

不得因为剪贴板页面点击而产生：

NullPointerException
IllegalStateException
Crash

==================================================
七、搜索功能
==================================================

删除原有：

【搜索】按钮。

保留搜索输入框。

例如：

┌──────────────────────────┐
│ 搜索剪贴板内容            │
└──────────────────────────┘

用户输入内容时：

【立即搜索】

不需要点击任何按钮。

例如用户输入：

a

立即刷新。

输入：

ad

立即刷新。

输入：

adb

立即刷新。

==================================================
八、实时搜索要求
==================================================

搜索必须支持：

- 实时更新
- 不区分大小写
- 匹配文本任意位置

例如：

搜索：

adb

可以匹配：

adb shell
ADB devices
xxx adb xxx

搜索结果仍然按照：

最新 → 最旧

排序。

==================================================
九、搜索结果序号
==================================================

搜索结果中的序号：

必须保留原始历史记录序号。

例如原始：

8 Hello
7 World
6 adb shell
5 Test
4 adb devices

搜索：

adb

显示：

6 adb shell
4 adb devices

不能重新编号为：

2 adb shell
1 adb devices

原因：

用户需要通过序号知道它在原始历史中的位置。

==================================================
十、清理重复功能
==================================================

新增：

【清理重复】

按钮。

功能：

扫描当前剪贴板历史。

如果发现多条记录的：

【原始文本内容完全一致】

则：

只保留最新的一条。

删除所有旧的重复记录。

==================================================
十一、完全一致的定义
==================================================

当前版本必须使用严格字符串比较。

例如：

"Hello"

和：

"Hello"

是重复。

但是：

"Hello"

和：

"hello"

不是重复。

"Hello"

和：

"Hello "

不是重复。

"Hello\nWorld"

和：

"Hello World"

不是重复。

禁止在清理重复时自动：

- trim
- 转小写
- 删除空格
- 删除换行
- 修改 Unicode
- 修改文本内容

当前版本只做：

【完全相同字符串去重】

==================================================
十二、去重保留规则
==================================================

例如：

8 Hello
7 World
6 Hello
5 Test
4 Hello

执行清理重复：

保留：

8 Hello
7 World
5 Test

删除：

6 Hello
4 Hello

因为：

8 Hello 是最新的 Hello。

==================================================
十三、清理重复后的重新排序
==================================================

删除重复记录后：

必须重新计算 UI 序号。

例如清理前：

8 Hello
7 World
6 Hello
5 Test

清理后：

实际剩余：

Hello
World
Test

重新显示：

3 Hello
2 World
1 Test

注意：

数据库 ID 不得因为重新排序而改变。

只有 UI 显示序号重新计算。

==================================================
十四、清理重复与搜索的关系
==================================================

如果用户当前正在搜索：

仍然允许执行清理重复。

清理重复必须针对：

【当前剪贴板历史全部记录】

而不是只针对当前搜索结果。

清理完成后：

重新加载当前分类。

重新执行当前搜索关键词。

保证 UI 状态连续。

==================================================
十五、网址自动分类
==================================================

自动识别：

- http://
- https://
- 常见 URL
- 网站地址
- 深链接
- 常见 URI Scheme

例如：

https://example.com

http://192.168.1.1

myapp://abc

自动进入：

【网址】

分类。

不得要求用户手动标记。

==================================================
十六、数字自动分类
==================================================

自动识别：

- 电话号码
- 验证码
- 数字串
- 订单号
- 金额
- 常见数字型内容

不能简单使用：

contains(number)

作为唯一判断条件。

例如：

"我有123个苹果"

不应该因为包含数字就强制分类为数字。

应该使用合理的模式识别。

==================================================
十七、隐私分类
==================================================

【隐私】是特殊分类。

绝对禁止自动分类。

APP 不得因为：

- 看起来像密码
- 看起来像身份证
- 看起来像银行卡
- 看起来像 Token
- 看起来像账号

就自动加入隐私。

只能由用户主动执行：

【加入隐私】

例如：

长按记录
    ↓
加入隐私

或者：

更多
    ↓
标记为隐私

==================================================
十八、隐私数据保护
==================================================

隐私分类必须继续遵循项目已有的剪贴板隐私设计。

至少保证：

1. 不写入普通日志。
2. 不输出到 Debug Log。
3. 不明文保存到普通外部文件。
4. 不允许未经授权的 APP 读取。
5. 可以单独清理。
6. UI 可以默认隐藏敏感内容。
7. 用户主动查看后才显示明文。

不得因为新增分类功能而绕过已有安全机制。

==================================================
十九、收藏
==================================================

收藏使用：

isFavorite

或等效状态字段。

不要把收藏设计成：

category = FAVORITE

因为一条记录可能同时：

网址 + 收藏

数字 + 收藏

隐私 + 收藏

因此：

【收藏必须是独立标签】

用户可以：

收藏
取消收藏

收藏分类显示：

所有 isFavorite == true 的记录。

==================================================
二十、数据结构建议
==================================================

在不破坏现有数据库结构的前提下，数据模型至少应能够表达：

id
content
createdAt
category
isFavorite
isPrivate

其中：

category：

URL
NUMBER
其他内部必要类型

isFavorite：

true / false

isPrivate：

true / false

注意：

【不要为了 UI 分类而强行破坏现有数据结构。】

如果现有架构已经能够实现上述功能：

优先复用。

==================================================
二十一、分类栏 UI
==================================================

建议分类栏：

全部
网址
隐私
数字
收藏

例如：

全部 | 网址 | 隐私 | 数字 | 收藏

保持当前项目已有 UI 风格。

不要重新设计整个剪贴板页面。

只进行实现这些功能所需的最小 UI 修改。

==================================================
二十二、剪贴板记录 UI
==================================================

每条记录开头显示：

UI 序号。

例如：

8  https://example.com

7  Hello World

6  adb shell

序号必须清晰。

不要把序号写入实际剪贴板文本。

也就是说：

用户点击：

8  Hello World

实际粘贴内容必须是：

Hello World

不能粘贴：

8 Hello World

==================================================
二十三、长按功能
==================================================

如果当前项目已经支持长按：

继续保留。

可以提供：

- 收藏
- 取消收藏
- 加入隐私
- 移出隐私
- 删除
- 其他已有功能

不要因为本次修改删除已有功能。

==================================================
二十四、导航
==================================================

剪贴板页面属于：

【输入法内部功能页面】

不是独立 APP 页面。

点击剪贴板记录完成粘贴后：

必须返回上一层输入法功能页面。

不能：

- 打开 Activity
- 退出输入法
- 关闭整个键盘
- 返回宿主 APP 页面

==================================================
二十五、性能
==================================================

实时搜索必须避免：

每输入一个字符都执行大量阻塞 IO。

优先：

内存过滤。

如果数据量较大：

使用适当的 debounce / 异步搜索。

搜索不能阻塞主线程。

清理重复：

不得长时间阻塞 UI。

数据库操作：

不得在主线程执行大量 IO。

a

8
7

==================================================
二十七、安全测试
==================================================

特别检查：

搜索功能不能把隐私内容输出到日志。

清理重复不能把隐私内容输出到日志。

分类检测不能把隐私内容输出到日志。

Debug 日志禁止输出：

剪贴板明文。

隐私内容。

密码。

Token。

Cookie。

验证码。

二十九、修改原则
==================================================

禁止：

- 重写整个剪贴板模块
- 修改无关功能
- 修改输入法 UI 主体
- 修改语音输入

优先：

复用已有架构。

保持现有 UI。

保持现有行为。
```
