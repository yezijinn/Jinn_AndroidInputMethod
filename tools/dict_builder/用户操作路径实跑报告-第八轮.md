## 二、核心发现：剪贴板历史页不可达

### 证据

```
Manifest:  android:name=".ClipboardHistoryActivity"
           android:exported="false"          ← 已注册，但禁止外部启动
启动代码:  grep 全项目 → 无任何 startActivity 调用点
```

### 问题描述

`ClipboardHistoryActivity` 是一份**完整实现（719 行）**的剪贴板历史页——
分类栏、动态序号、实时搜索、去重、长按菜单、点击粘贴广播回传全部具备，
`AndroidManifest.xml` 中也已注册。但：

1. **没有任何 UI 入口能到达它**（键盘内嵌面板与搜索面板都不跳转此页）
2. **`exported="false"`** 使 adb 与外部应用也无法启动

即：**这是一个实现了但用户永远看不到的页面。**

### 为什么这构成问题（而非"无害的遗留代码"）

**项目约定明确写着**：

> 剪贴板内容有**三个**展示入口，任何隐私/安全相关改动**必须三处同步**

而实际可达的只有 **2 个**。由此产生两个实际影响：

1. **约定与实际不符** —— 后续维护者按"三处同步"操作时，会在一处根本测不到的代码上花费精力
2. **维护负担虚高** —— 该文件的共享逻辑引用数反而**最多**（`ClipboardFilter`/分类/隐私
   相关引用 17 处，多于内嵌面板的 13 处、搜索面板的 4 处），意味着"三处同步"这条
   约定的成本主要压在一个不可达文件上

### 判定

**需要用户决策，不宜自行处理**：

- 若该页是**有意下线**的 → 应删除该 Activity 与 Manifest 声明，
  并把约定改为"两处入口"，消除维护负担
- 若是**遗漏入口** → 应在键盘面板或设置页补一个跳转

两种方向的改动性质完全不同，且涉及"是否保留独立历史页"的产品决策，
因此本轮**只报告不修改**。

### 复现方式

无法通过 UI 复现（正是问题所在）。验证方式为静态检索：

```bash
# 应无输出（证明无启动点）
grep -rn "ClipboardHistoryActivity::class" app/src/main/java/
# 应为 exported="false"（证明外部也无法启动）
grep -A 3 "ClipboardHistoryActivity" app/src/main/AndroidManifest.xml
```

## 四、备注：为何入口 2 未做点击验证

顶部搜索面板的触发按钮位于键盘面板内部，而该区域是**自定义 View 绘制**，
`uiautomator` 无法枚举其子节点，只能按截图比例换算坐标驱动。实测中：

- 换算出的坐标可稳定命中字母键（如功能行「双拼」按钮一次命中）
- 但**同一功能行内的「搜索」按钮连试 9 个邻近坐标均未命中**，
  分类栏的「返回」按钮亦未命中

因此判断为**驱动方式不可靠**（而非按钮无响应）：键盘面板内部的触摸判定
与截图坐标的映射关系不是线性等比。此项**未取得有效结论**，
代码层已确认 `searchPanel.isActive()` 有正常调用链，功能应可用。

**结论**：入口 2 的可达性**未验证**（`unverified`），不作为缺陷上报。

## 五、方法备注

- **每次操作前重新确定坐标**：本轮再次踩到坐标失效——页面状态变化后
  控件位置会移动，复用旧坐标必然点空（判据：日志完全为空）。
- **键盘类自定义 View 不要依赖截图比例换算**：字母键区域可命中，
  但功能行/分类栏的命中区与换算值存在偏差，应改用「先用已知可命中点校准
  比例，再推导目标点」的方式，或直接放弃 adb 驱动改用人工点验。
- **日志 grep 要限定应用 tag**：本轮一次误报源于 `grep search` 命中了
  系统的 `avc: denied { search }` SELinux 日志。
