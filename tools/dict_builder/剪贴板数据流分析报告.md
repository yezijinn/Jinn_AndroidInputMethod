## 一、完整功能流程（12 个环节）

```
[系统剪贴板变化]
      │  ① ClipboardManager.OnPrimaryClipChangedListener（主线程回调）
      ▼
[ClipboardController.onClipboardChanged]
      │  ② ownCommit 过滤：3 秒窗口内的自身写入 → 直接 return
      │  ③ primaryClip == null → 后台延迟 250ms 重试一次（应对 Android 10+ 时序/权限边界）
      ▼
[内容提取]
      │  ④ itemCount == 0 守卫 → getItemAt(0).coerceToText() → isBlank 判空
      │  ⑤ resolveSourcePackage()：保守返回本包名（系统剪贴板不携带可靠来源）
      ▼
[切后台线程]  ⑥ BackgroundIo.run —— 主线程零阻塞
      ▼
[ClipboardStore.save]
      │  ⑦ 自动分类：ClipboardClassifier.classify（URL > NUMBER > OTHER；隐私绝不自动）
      ▼
[ClipboardDb.upsert]
      │  ⑧ 加密：ClipboardCrypto.encrypt（AES-256-GCM + Android Keystore）
      │     失败 → 返回 -1（不写入、不崩溃）
      │  ⑨ 去重：stableHash = SHA-256 → findIdByHash
      │     命中 → 只更新元数据 + 置顶，**保留收藏/隐私标记**
      │     未命中 → INSERT
      │  ⑩ 裁剪：trimTo(maxItems) —— 删最旧非收藏，事务包裹，收藏豁免
      ▼
[存储层]
      └─ SQLite（正文为密文，content_hash 唯一索引）
      ▼
[展示：ClipboardPanelView]
      │  ⑪ 分页读取（recentPage 只解密本页）+ 稳定 itemId 查找
      ▼
[粘贴回传]
      │  ⑫ 广播只传 id（规避 Binder 1MB 事务上限）→ IME 按 id 回读 → commitText
      └─ 结果回传带 itemId 防串线，带 runCatching
```

**环节数 12 ≥ 闸门要求的 5** ✓

## 二、关键处理环节的深度核查

### 环节 ②：`ownCommit` 过滤（防"误杀用户真实复制"）

| 项 | 实现 | 判定 |
|---|---|---|
| 标记置位 | 仅 `onOwnCommit()`（粘贴路径） | ✅ 符合约定 |
| 过期处理 | `OWN_COMMIT_WINDOW_MS = 3000L` 窗口判断 | ✅ 超出窗口的标记不拦截 |
| 标记清除 | 拦截与放行两条路径都清除 | ✅ 无残留 |

**这是约定特别警告的陷阱**（"标记残留会把用户真实复制误杀"），实现比要求更严谨。

### 环节 ③：`primaryClip == null` 的 250ms 重试

Android 10+ 后台进程读 `primaryClip` 可能拿到 `null`（系统尚未完成写入，或进程刚退到后台）。
实现选择**延迟 250ms 后台重试一次**，而非直接丢弃。

**判定**：✅ 合理的工程折中。代价是 `Thread.sleep(250)` 占用一个后台线程任务槽，
但 `BackgroundIo` 是单线程调度器，该 sleep 会短暂阻塞队列 —— **低概率、低影响**（`confidence: high`）。

### 环节 ⑧⑨：加密与去重

| 项 | 实现 | 判定 |
|---|---|---|
| 加密算法 | AES-256-GCM + Android Keystore（`base64(iv):base64(cipher)`） | ✅ |
| 加密失败 | `?: return -1`，不写入 | ✅ 不崩溃 |
| 去重哈希 | **SHA-256**（非 `hashCode()`） | ✅ 碰撞概率可忽略 |
| 已存在时 | 只更新元数据 + 置顶，**不动收藏/隐私** | ✅ 符合约定 |

### 环节 ⑩：`trimTo` 裁剪

```kotlin
if (maxItems <= 0) return                                    // 守卫
val count = count(); if (count <= maxItems) return
val overflow = count - maxItems
// 优先删非收藏最旧记录；收藏永远保留
SELECT id FROM items WHERE is_favorite = 0 ORDER BY created_at ASC LIMIT $overflow
if (ids.isEmpty()) return // 全部是收藏，不裁剪
beginTransaction() { delete each } / endTransaction()         // 事务包裹
```

✅ 收藏豁免正确、全收藏时不裁剪、事务包裹、`overflow` 为内部计算的 Int（无注入）。

### 环节 ⑫：粘贴回传

```kotlin
// 粘贴广播只传 id：正文不随广播走（Binder 事务上限约 1MB，长文本会崩），
// 改由 IME 按 id 从数据库读回
```

✅ **规避了 `TransactionTooLargeException`** —— 长文本粘贴不会崩溃。
结果回传带 `itemId`（防异步串线），且 `runCatching` 包裹。

## 三、发现的问题

### 问题 1：隐私记录不豁免裁剪（设计问题，非缺陷）

**位置**：`ClipboardDb.kt:301-311`

**事实**：`trimTo` 只豁免 `is_favorite = 1`，`is_private = 1` 的记录会随"最旧非收藏"被删除。

**证据**：
- 源码 `WHERE is_favorite = 0`
- 注释（L14 / L293-294）也只写"收藏豁免"，**未提及隐私**

**即：代码、注释、约定三者一致** —— 这是**有意设计**，不是遗漏。

**但值得商榷**：隐私是用户**刻意主动标记**的（约定："隐私只能用户手动标记，绝不自动"），
语义上比收藏更敏感。用户标记隐私后又因容量上限被自动删除，可能违反直觉。

**严重级别**：P3（设计建议，非缺陷）
**置信度**：high（三处证据一致）

**可选方案**：
- 方案 A：`WHERE is_favorite = 0 AND is_private = 0`（隐私同样豁免），
  代价是隐私记录多时可能无法有效裁剪，需同步考虑"全隐私"场景的处理
- 方案 B：保持现状，但把"隐私不豁免"写进约定文档，消除歧义
- 方案 C：裁剪时优先删非收藏，其次删非隐私，最后才考虑隐私

**建议**：需要你决定产品语义，我不宜替选。

### 问题 2：`trimTo` 无测试覆盖（测试缺口）

**位置**：`app/src/test/java/.../` —— 无 `trimTo` 相关用例

**原因**：`trimTo` 依赖 SQLite（Android 依赖 4 个），纯 JVM 单测不可达；
补齐需引入 Robolectric，而项目无此依赖。

**严重级别**：P3（覆盖率缺口）
**置信度**：high

**说明**：这与上一轮结论一致 —— 剪贴板模块中依赖 Android 的部分（Crypto/Db/Controller/Prefs/Firewall）
**均无法纯 JVM 覆盖**，只能靠真机验证。**不是本模块特有的问题**。

### 问题 3（提醒项）：`resolveSourcePackage()` 恒返回本包名

**位置**：`ClipboardController.kt:100`

所有历史条目的"来源应用"都显示为**本输入法**，而非真实复制来源。

**判定**：**有意设计** —— 代码注释明确说明：
> 系统剪贴板本身不携带可靠来源信息……来源追踪留待 Root 增强模式从 ClipboardService 层获取

**严重级别**：P4（已知限制，不做建议）
**置信度**：high

## 四、未发现缺陷的维度（逐项核查记录）

| 维度 | 核查结果 |
|---|---|
| **边界条件** | `itemCount == 0` 守卫、`content.isBlank()` 守卫、`maxItems <= 0` 守卫、`ids.isEmpty()` 守卫 —— 四处齐全 |
| **异常处理** | 加密失败返回 `-1`、广播失败 `runCatching`、`coerceToText` 可空处理 —— 无静默吞异常 |

| **SQL 安全** | `whereClause()` 动态部分仅 `category`，用 `?` 占位绑定 |
| **类型使用** | `coerceToText()` 可空链式处理，无 `!!` |
| **隐私保护** | 不输出剪贴板正文日志；正文加密存储 |

剪贴板模块在**异常处理、边界守卫、资源管理、并发调度、SQL 安全**五个维度上
