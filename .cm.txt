剪贴板模块废弃代码排查：模块本身已无废弃，顺带清掉 2 个废弃 drawable

【排查方法】对剪贴板 8 个文件做全量引用统计
按「函数 / 属性 / 常量 / 类 / 资源」五个层面逐一核对引用者：
- 提取所有函数定义，全项目（含测试）统计调用次数
- 提取所有 val / const val，统计字段级引用
- 检查每个类的跨文件引用
- 检查 drawable 与 string 资源的引用

【结论一：剪贴板模块代码已无废弃】
- 函数层面：非 override 函数零引用者 **0 个**
- 属性/常量层面：零引用者 **0 个**
- 类层面：8 个类全部有跨文件引用
  （ClipboardController←JinnIme、ClipboardDb←5 处、ClipboardCrypto←ClipboardDb、
   ClipboardClassifier←3 处、ClipboardPrefs←4 处、ClipboardFirewall←SettingsActivity、
   ClipboardPanelView←PinyinKeyboardView、SearchPanelView←2 处）
- 说明：上一轮删除 deduplicate() / mergeDedupeFlags() / 隐私代码后，模块已清理干净

【排查中确认「不是废弃」的项（避免误删）】
- BaseAdapter 的 getCount/getItem/getItemId/getView、OnScrollListener 的 onScroll/
  onScrollStateChanged、TextWatcher 的三个回调 —— 均由框架调用，无显式调用者但必需
- clipboard_max_items_title / _hint —— 被 activity_settings.xml 引用
- rootEnhanceEnabled —— 被 SettingsActivity 读写（开关 + Root 不可用时自动关闭）
- ClipboardFirewall 的 7 个 check* 方法 —— 全部被 audit() 调用（7:7）
- btn_aurora_primary / btn_aurora_secondary —— **首次误判为废弃并删除，编译立即报错**，
  实为被 values/styles.xml 的 SettingsButton / SettingsButtonPrimary 引用（12 处 / 1 处），
  已 git checkout 恢复

【结论二：顺带清理 2 个真正废弃的 drawable】
- card_bg.xml、field_bg.xml：全 res 与 Kotlin 均无引用
  （注意 @color/card_bg 是同名**颜色**，被 card_aurora.xml 使用，已保留）
- 验证方式：删除后 assembleDebug + lintDebug 通过（仅 compileDebugKotlin 不足以验证资源引用）
- 真机确认设置页完整渲染，无 Resources.NotFoundException

【方法教训】
1. grep 检查资源引用时**必须覆盖 values/ 目录**（style/theme 也在那里引用 drawable），
   只查 layout/ 会漏
2. **字段名匹配要防 \b 边界误判**：rootEnhance 匹配不到 rootEnhanceEnabled
3. **验证资源删除的最可靠手段是编译 + assembleDebug + lintDebug**，grep 只能做初筛
